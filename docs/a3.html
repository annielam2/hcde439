Assignment 3: Smart Night Light

HCDE 439 Physical Computing · a light-sensing smart home prototype

For our smart home company, I prototyped a Smart Night Light that senses how much light is in a room and shows it in two ways. A photoresistor measures the room's brightness. As the room gets darker, a yellow “lamp” LED smoothly fades in, so a hallway or kid's room is never fully dark, and it fades back out when daylight returns. A red NIGHT LED turns on when the room drops below a dusk threshold, the moment a real system might also close the blinds or turn on the porch light. The Arduino also reports the light level over serial, the way a smart home hub would log sensor data.

Calculations

What will I read at the voltage divider?

With the photoresistor on top (R1) and the fixed resistor on the bottom (R2), the voltage at A0 is:

Vmeasure = 5 V × R2 / (R1 + R2)

and analogRead() turns 0–5 V into a number from 0–1023, so reading = Vmeasure × 1023 / 5.

The photoresistor in my kit (a GL5528-type cadmium sulfide cell) is about 2 kΩ with a phone flashlight shining on it, about 10 kΩ in normal room light, and about 50 kΩ when I cover it with my hand. With R2 = 10 kΩ:

SituationR1 (photoresistor)Vmeasure = 5 × 10k / (R1 + 10k)analogRead()
Flashlight (bright)2 kΩ5 × 10 / 12 = 4.17 V853
Room light10 kΩ5 × 10 / 20 = 2.50 V512
Dusk (night threshold)15.6 kΩ5 × 10 / 25.6 = 1.96 V400
Covered by hand (dark)50 kΩ5 × 10 / 60 = 0.83 V171

So I expect readings between about 170 (dark) and 850 (bright), which are the calibration values used in my code.

Choosing R2 (the fixed resistor)

The best fixed resistor puts the sensor's range in the middle of the 0–5 V window. Because a photoresistor's resistance changes by a factor (2 kΩ to 50 kΩ is 25×), the right middle is the geometric mean, not the average:

R2 = √(Rlow × Rhigh) = √(2,000 Ω × 50,000 Ω) = √100,000,000 = 10,000 Ω = 10 kΩ

10 kΩ is 5× bigger than 2 kΩ and 5× smaller than 50 kΩ, so it sits proportionally in the center. To check, here is the voltage swing (bright V − dark V) for a smaller and larger resistor:

R2Bright (R1 = 2k)Dark (R1 = 50k)Swing
1 kΩ5 × 1/3 = 1.67 V5 × 1/51 = 0.10 V1.57 V
10 kΩ4.17 V0.83 V3.33 V
100 kΩ5 × 100/102 = 4.90 V5 × 100/150 = 3.33 V1.57 V

10 kΩ gives more than twice the swing of either neighbor, which means more analogRead() steps (about 680 of the 1024) between dark and bright and a smoother fade. It also keeps the divider's current tiny: at most 5 V / (2 kΩ + 10 kΩ) = 0.42 mA.

LED resistors (R3 and R4)

Same as A2: Rmin = (5 V − 2.0 V) / 0.020 A = 150 Ω, so I used the next standard value, 220 Ω, giving about (5 − 2.0) / 220 = 13.6 mA for red and (5 − 2.1) / 220 = 13.2 mA for yellow.

Circuit

Firmware

Every 100 ms, the sketch:

  1. Reads V-measure with analogRead(A0), a number from 0 (0 V) to 1023 (5 V).
  2. Constrains it to 170–850, the dark (0.83 V, sensor covered) to bright (4.17 V, flashlight) range from my calculations, so a reading slightly outside that range can't push map() below 0 or above 255.
  3. Maps it with map(clamped, 170, 850, 255, 0). The output range is flipped on purpose: the darkest reading (170) gives full brightness (255) and the brightest (850) gives 0, so the lamp fades in as the room gets darker. 255 is the top because analogWrite() is 8-bit. analogWrite() then sets the yellow LED's brightness.
  4. Checks for night with an if-statement: if the reading is below 400 (1.96 V, meaning the photoresistor is above about 15.6 kΩ, a dim, dusk-like room), the red NIGHT LED turns on; otherwise it's off. I picked 400 because it's clearly below normal room light (512), so a passing shadow doesn't trigger night mode, but well above a covered sensor (170).
  5. Prints Room light level: followed by the reading, so I can watch it in the Serial Monitor and graph it for Question 2.

The sketch is also in my repo at a3/a3.ino.

// Analog pin connected to V-measure, the middle of the photoresistor / 10k voltage divider
const int SENSOR = A0;
// Red NIGHT LED (on when the room is dark)
const int RED = 9;
// Yellow lamp LED (fades with PWM, so it must be on a PWM pin ~)
const int LAMP = 11;

// setup() runs once when the Arduino starts
void setup() {
  // Start serial communication at 9600 baud so readings show in the Serial Monitor
  Serial.begin(9600);
  // Set the red LED pin as an output
  pinMode(RED, OUTPUT);
  // Set the lamp LED pin as an output
  pinMode(LAMP, OUTPUT);
}

// loop() runs over and over forever
void loop() {
  // Read V-measure as 0-1023 (0-5 V): about 170 when covered (dark), 850 under a flashlight (bright)
  int light = analogRead(SENSOR);
  // Keep the reading between 170 and 850 so map() never goes below 0 or above 255
  int clamped = constrain(light, 170, 850);
  // Map dark (170) to full brightness (255) and bright (850) to off (0): the darker the room, the brighter the lamp
  int brightness = map(clamped, 170, 850, 255, 0);
  // Set the lamp LED's brightness with PWM
  analogWrite(LAMP, brightness);

  // If the reading is below 400 (about 1.96 V, a dim room at dusk)...
  if (light < 400) {
    // ...it's night, so turn the red LED on
    digitalWrite(RED, HIGH);
  // Otherwise there is enough daylight
  } else {
    // Turn the red LED off
    digitalWrite(RED, LOW);
  }

  // Print a label for the light level
  Serial.print("Room light level: ");
  // Print the reading and start a new line
  Serial.println(light);
  // Wait 100 ms, so there are 10 readings per second
  delay(100);
}

Questions

1. Can the variable resistor be either R1 or R2?

Either position works. Swapping them doesn't change how much the voltage swings; it only flips its direction, and the code has to be flipped to match.

Photoresistor as R1 (top, my circuit): V = 5 × 10k / (Rphoto + 10k)

  • Bright (2 kΩ): 5 × 10 / 12 = 4.17 V → reading 853
  • Dark (50 kΩ): 5 × 10 / 60 = 0.83 V → reading 171
  • More light = higher voltage.

Photoresistor as R2 (bottom), 10 kΩ on top: V = 5 × Rphoto / (10k + Rphoto)

  • Bright (2 kΩ): 5 × 2 / 12 = 0.83 V → reading 171
  • Dark (50 kΩ): 5 × 50 / 60 = 4.17 V → reading 853
  • More light = lower voltage.

Both give the same 3.33 V swing (171 to 853), so the sensor is equally sensitive either way. The difference is only in the code: with the photoresistor on the bottom, dark gives the high reading, so I would write map(clamped, 170, 850, 0, 255) (no flip needed for the lamp) and turn on the red LED with if (light > 623) (the mirror of 400: 1023 − 400 = 623). What matters is that one resistor is variable and the other is fixed. If both were fixed the voltage would never change, and without the fixed resistor there would be no divider at all, so A0 would always read 5 V.

3. 10-bit PWM and a 16-bit ADC

Right now analogRead() is 10-bit (210 = 1024 values, 0–1023) and analogWrite() is 8-bit (28 = 256 values, 0–255). With a 16-bit ADC the reading would range 0–65,535, and with 10-bit PWM the output would range 0–1023. The same voltage would just be described with finer steps, so every number on each side of map() has to be rescaled:

  • Input side: a 16-bit reading is 216 / 210 = 64× larger for the same voltage. My dark and bright calibration values become 170 × 64 = 10,880 and 850 × 64 = 54,400 (check: 0.83 V × 65,535 / 5 ≈ 10,900 and 4.17 V × 65,535 / 5 ≈ 54,650). The night threshold becomes 400 × 64 = 25,600.
  • Output side: full brightness is now 1023 instead of 255.
// before: 10-bit ADC in, 8-bit PWM out
int lampBrightness = map(clamped, 170, 850, 255, 0);

// after: 16-bit ADC in, 10-bit PWM out
long lampBrightness = map(clamped, 10880, 54400, 1023, 0);

One more catch: on the Uno an int only holds up to 32,767, so a 16-bit reading (up to 65,535) wouldn't fit. The reading would need to be stored as unsigned int or long. The result is the same behavior, the lamp still goes from fully on in the dark to off in bright light, but with 64× finer input steps and 4× finer brightness steps, so the fade would be even smoother.
